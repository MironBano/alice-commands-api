# Android — UX чипов `device_types` (поверхности Алисы)

**Статус:** ТЗ для app-агента · **Дата:** 2026-07-08  
**Репозиторий реализации:** [AliceCommands](https://github.com/MironBano/AliceCommands) (Android, Full Clean)  
**Backend (контракт, без обязательных правок):** alice-commands-api · `schema/content-bundle.schema.json`  
**idea_ref:** MOB-20260626-001

---

## 1. Контекст и проблема

В app на экране **категории команд** показывается горизонтальная строка чипов: **«Все / Колонка / ТВ / Телефон»** (точные подписи могут отличаться).

По контракту bundle поле `device_types` означает **не тип IoT-устройства** (лампочка, розетка, чайник), а **поверхность, с которой пользователь обращается к Алисе**:

| Значение | Смысл |
| -------- | ----- |
| `station` | Колонка / устройство с Алисой |
| `tv` | Умный ТВ с Алисой |
| `phone` | Смартфон (Яндекс / Дом с Алисой) |

Чипы строятся из `categories[].device_types`. Фильтрация — по пересечению с `commands[].device_types` (команда видна, если выбранный тип входит в массив команды).

### Почему UX ломается в «Умном доме»

Категория `smart_home`: 100 команд. При выборе чипа скрывается почти ничего:

| Чип | Команд скрыто | Комментарий |
| --- | ------------- | ----------- |
| Все | 0 | — |
| Колонка | 0 | у всех 100 есть `station` |
| Телефон | 0 | у всех 100 есть `phone` |
| ТВ | **8** | только команды «свет в &lt;комната&gt;» без `tv` |

92 % команд помечены `["station", "phone", "tv"]`, поэтому на «ТВ» остаются розетки, кондиционеры и т.д. Пользователь ожидает фильтр по **умным устройствам**, а получает фильтр по **месту голосового ввода** — строка чипов вводит в заблуждение и не даёт пользы.

**Решение продукта:** убрать строку чипов **только** на экране категории `smart_home`. На остальных категориях — **не убирать**, но сделать смысл чипов понятным.

### Справка по всему каталогу (staging v51+, `seed/catalog-audit-fixed.json`, 871 команд)

Скрытие команд при выборе одного чипа (без «Все»):

| category_id | Чипы в категории | Команд | Скрытий (max по чипам) |
| ----------- | ---------------- | ------ | ---------------------- |
| `smart_home` | station, phone, tv | 100 | **8** (только ТВ) |
| `alice_plus` | station, phone | 21 | 4 (phone) |
| Остальные multi-chip | … | … | **0** |

Итого: осмысленный фильтр сейчас почти нигде не работает; после фикса УД приоритет — **понятность подписей**, а не «магия фильтра».

## 4. Экраны и поведение

### 4.1. Категория `smart_home` — убрать чипы

**Экран:** список групп/команд категории «Умный дом» (`category_id == "smart_home"`).

**Было:** строка чипов Все / Колонка / ТВ / Телефон под шапкой категории.

**Стало:**
- Строка чипов **не рендерится** (высота 0, без пустого placeholder).
- Список групп показывает **все** команды категории (эквивалент чипа «Все»).
- Состояние «выбранный device filter» для этой категории **не сохранять** в UI state / не восстанавливать при повторном входе (или принудительно сбрасывать в `ALL` при `categoryId == smart_home`).

**Навигация с экрана «Устройства»:** если guide открывает каталог с `command_device_filter_id` (station/tv/phone) — для `smart_home` **игнорировать** preselected filter и показывать полный список (см. §6).

### 4.2. Остальные категории — понятность UI

Применяется, если `categories.device_types.size >= 2` (сейчас: general, music, audiobooks, tv_video, quick_answers, timers, calls, alice_plus, quick_commands).

#### 4.2.1. Подписи чипов (рекомендуемый канон)

| `device_types` | Было (пример) | Стало |
| -------------- | ------------- | ----- |
| (все) | Все | **Все** |
| `station` | Колонка | **Колонка** |
| `tv` | ТВ | **С ТВ** |
| `phone` | Телефон | **С телефона** |

Короткие подписи в чипе; полная формулировка — в подсказке (§4.2.2).

Для категории **только с `station`** (`kids`, `obscure`, `station_settings`) строка чипов как сейчас **не показывается** (одна поверхность) — поведение не менять.

#### 4.2.2. Поясняющий текст под строкой чипов

Под `FilterChipRow` (или над списком групп) — **одна строка** `bodySmall`, цвет `onSurfaceVariant`:

> **Где вы говорите с Алисой** — не какое устройство умного дома управляете.

- Показывать **только** когда строка чипов видима.
- При скролле списка можно скрывать вместе с чипами (sticky header — по желанию, не обязательно).
- Локализация: строка в `strings.xml` (`device_filter_hint`).

#### 4.2.3. Пустой результат фильтра

Если после выбора чипа **0 команд** (редко; возможно в `alice_plus` / частично `smart_home` до фикса):

- Не пустой экран без объяснения.
- Текст: «Нет команд для этого способа управления. Выберите «Все» или другой вариант.»
- Кнопка или чип «Все» остаётся доступным.

#### 4.2.4. Accessibility

- `contentDescription` чипов: «Показать команды, которые можно сказать с колонки» / «…с телевизора» / «…с телефона».
- Подсказка §4.2.2 — читается TalkBack при фокусе на region заголовка фильтра.

## 5. Данные и логика (без изменений контракта)

```
categories[].device_types  →  какие чипы показать (кроме smart_home — не показывать)
commands[].device_types    →  команда проходит фильтр, если selected in command.device_types
command_groups             →  структура списка (Свет / Климат / …) — не менять
```

Фильтрация на уровне **команд**; группа видна, если видна хотя бы одна команда группы (если в app иначе — зафиксировать в PR и не менять в этой задаче без согласования).

**Backend менять не нужно.** Опционально в будущем: убрать `device_types` у категории `smart_home` в bundle — app всё равно должен работать по `category_id`.

## 6. Краевые случаи

| Сценарий | Ожидание |
| -------- | -------- |
| Deep link / guide → каталог `smart_home` с `filter=tv` | Показать все команды УД, filter игнорировать |
| Пользователь выбрал «ТВ» в music, ушёл в smart_home | В smart_home чипов нет; в music при возврате — восстановить «ТВ» |
| Offline, старый bundle без `device_types` | Чипы не показывать (fallback как сейчас) |
| Поворот экрана | Состояние чипа сохраняется (кроме smart_home) |
| Tablet / landscape | Подсказка не переносится на 3+ строки без `maxLines` |

## 7. Критерии приёмки (DoD)

### Умный дом
- [ ] На категории `smart_home` нет горизонтальной строки чипов.
- [ ] Отображаются все 100 команд (все группы: Свет, Климат, Устройства, Охрана).
- [ ] Нет регрессии скролла, поиска, раскрытия групп, command detail.

### Остальные категории
- [ ] Подписи чипов: Все / Колонка / С ТВ / С телефона (или согласованный вариант из §4.2.1).
- [ ] Видна подсказка «Где вы говорите с Алисой…».
- [ ] `tv_video`: чипы Все / Колонка / С ТВ (без «С телефона») — по `device_types` категории.
- [ ] Категории только с `station` — без строки чипов (как сейчас).

### Техническое
- [ ] Unit-тесты на правило «smart_home → hide chip row» (ViewModel / use case).
- [ ] Compose UI test или screenshot test: smart_home без чипов; music с подсказкой (по возможности проекта).
- [ ] `./gradlew test` (или модуль app) — green.

### Ручная проверка (QA)
- [ ] Умный дом → нет чипов, видны розетки и климат.
- [ ] Музыка → есть чипы + подсказка; переключение не крашит.
- [ ] ТВ и видео → чип «С ТВ» понятен в контексте подсказки.
- [ ] TalkBack: чипы озвучиваются с «с колонки / с ТВ / с телефона».
